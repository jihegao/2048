# 校园 2048 在线挑战平台 · UI 设计规范

## 1. 设计目标

界面围绕三个优先级设计：比赛状态可快速识别、多人比分可持续阅读、学生操作路径尽量短。学生进入平台后可在首页、房间大厅和挑战模式之间直接跳转；比赛中不需要切页即可看到本人、队友和对手成绩。

## 2. 信息架构

### 学生端

- 首页概览
- 房间大厅
- 单人练习
- 1v1 对抗
- 组队挑战
- 排行榜
- 比赛实况

### 教师端

在学生端公共页面基础上增加：

- 新建和管理比赛房间
- 参与人数与掉线状态监控
- 异常操作复核
- 服务健康状态
- 赛事待办和结算入口

## 3. 核心比赛页面规则

### 1v1

顶部先显示剩余时间；第二层显示双方总分与实时分差；棋盘区域只突出本人操作；右侧提供对手最高方块、移动次数和事件流。分差为负时状态由绿色“你领先”切换为红色“正在追赶”。

### 组队赛

团队总分位于页面首屏；棋盘两侧分别为队友和对手实时得分；本人在队友列表中高亮；棋盘顶部展示本人得分、团队贡献率和最高方块。移动端先展示棋盘，再展示双方名单。

### 比赛实况

实况页不提供操作控件。页面顺序为：赛事身份、双方总分、得分走势、动态事件、双方队员列表。适合投屏和教师监控。

### 主色

```text
品牌紫高光     #7A70FF
比分蓝         #4F79ED
实时青         #24BDBB

页面背景       #F5F7FB
正文           #172238
次级文字       #7D8BA3

```

### 字体与层级

- 页面标题：23–38 px，粗体
- 模块标题：13–18 px，粗体
- 核心比分：20–38 px，使用等宽数字特性
- 说明文字：8–12 px
- 英文分区标签：大写、加粗、增加字距

### 容器

- 主面板圆角：16 px
- 棋盘圆角：18 px
- 控件圆角：8–11 px
- 面板使用低对比边框和轻阴影，避免比赛页面视觉噪声

## 5. 状态语义

- 绿色：在线、领先、验证通过、服务正常
- 红色：比赛中、追赶、异常、需复核
- 橙色：候场、即将开始、提醒
- 紫色：品牌操作、官方赛事、当前选中状态
- 灰色：未激活、结束、次要状态

不能只依赖颜色表达关键状态；状态标签同时包含文字，在线状态同时使用圆点。

## 6. 响应式规则

- 1240 px 以下：压缩侧栏和三栏比赛布局
- 1050 px 以下：部分三栏页面改为两栏，团队对手名单移动到下方
- 820 px 以下：侧栏改为抽屉，启用底部移动导航
- 620 px 以下：比赛页面改为单列，棋盘显示屏幕方向键
- 430 px 以下：进一步压缩比分卡片、榜单领奖台和队员列表

棋盘始终保持 1:1 比例，移动端不产生页面级横向滚动。

## 7. 交互与反馈

- 所有主要操作按钮需有悬停、键盘焦点和按下反馈
- 建房、登录、加入房间和筛选均使用轻量提示条反馈
- 比赛中显示网络延迟、在线状态或服务端验证状态
- 弹窗支持遮罩点击和 Esc 关闭
- 房间码输入自动大写并自动跳转到下一格
- 棋盘支持键盘、WASD、触摸滑动和屏幕方向键

## 8. 无障碍与比赛环境

- 保证关键文本与背景有明显对比
- 表格在窄屏容器内横向滚动，不扩大整个页面宽度
- 键盘焦点使用清晰外描边
- 比赛计时和比分使用稳定布局，数字变化时不引起大范围跳动
- 比赛实况适合 16:9 投屏，教师端优先展示全局状态

## 9. 前后端字段映射

```text
当前用户：studentId, displayName, className, role
房间：roomId, roomCode, mode, capacity, status, startsAt
比赛：matchId, seedMode, scoringRule, remainingMs, status
选手：playerId, teamId, score, maxTile, moveCount, connectionStatus
队伍：teamId, name, score, rank, onlineCount
事件：type, playerId, value, serverTime
```

所有比赛分数以服务端快照为准。浏览器只负责提交输入和显示状态，不能作为最终成绩的可信来源。
