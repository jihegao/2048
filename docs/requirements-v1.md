## 1. 文档目的

本文档把已确认的第一轮需求转化为可验收的产品规格，供产品评审、设计、开发和测试共同使用。

本轮目标是把现有纯前端演示原型重构为可真实登录、保存数据、创建房间并进行实时比赛的校园 2048 平台，同时将界面精简为教师端和学生端明确需要的功能。

## 2. 产品目标与成功标准

### 2.1 产品目标

1. 教师能够维护学生和团队，创建 1v1 或 3v3 房间，并实时查看所有参赛者棋盘与得分。
2. 学生能够查看自己的记录和团队，参加个人练习，并从公开房间列表加入比赛。
3. 手机和 iPad 能够通过棋盘滑动完成全部游戏操作，桌面端同时支持键盘。
4. 页面界面能够在简体中文和英文之间即时切换，且语言偏好跨登录保存。
5. 比赛状态、棋盘和成绩以服务端为权威来源；刷新或短暂掉线后能够继续比赛。
6. 第一轮可在 Cloudflare `workers.dev` 地址完成真实教师、学生和实时比赛验收。

### 2.2 量化成功标准

- 支持最多 1000 个学生账号。
- 支持 60 名学生同时参加比赛。
- 正式比赛时长只能为 1–10 分钟整数。
- 手机最小验收视口为 360×800 CSS 像素。
- iPad 同时验收 768×1024 与 1024×768。
- 中英文资源键必须 100% 对齐，不允许缺失翻译后静默上线。
- 结果结算必须幂等，同一房间不得产生重复比赛成绩。

## 3. 用户角色

### 3.1 管理员教师

第一轮只有一个管理员教师账号。该账号由部署流程安全初始化，不在产品界面中创建或删除。

教师可以：

- 查看教师首页概览。
- 创建、设置、取消和开始房间。
- 查看比赛实况和任意参赛者的大棋盘。
- 查看和导入学生账号。
- 单个或批量重置学生密码。
- 查看和导入团队。
- 移除团队单个成员或清空整队。
- 查看、筛选和导出正式比赛成绩。

教师不可以：

- 修改或删除已经结算的比赛成绩。
- 在比赛开始后修改模式、时长或参赛者。
- 通过界面创建其他教师账号。

### 3.2 学生

学生使用学号和密码登录。

学生可以：

- 查看学生首页概览。
- 查看自己的练习与正式比赛记录。
- 查找、加入和退出团队。
- 进行不限时个人练习。
- 查看公开房间、加入和退出候场。
- 在比赛中操作自己的棋盘。

学生不可以：

- 创建或设置比赛房间。
- 创建、重命名或删除团队。
- 查看其他学生的完整个人成绩。
- 查看其他参赛者的实时棋盘或分数。
- 查看教师管理页面。

- 通知铃铛、消息角标和待办事项。

- 房间码快捷加入。
- 独立的“1v1 对抗”和“组队挑战”一级导航。
- 学生端实时查看对手或队友比分。
- 旧 `standalone-demo.html` 的生产访问入口。

## 5. 中英文界面

### 5.1 支持语言

- `zh-CN`：简体中文。
- `en`：英文。

不支持繁体中文或其他语言。

### 5.2 首次语言选择

1. 未登录用户首次访问时读取 `navigator.languages`。
2. 首个以 `zh` 开头的首选语言使用 `zh-CN`，其他情况使用 `en`。
3. 用户手动切换后，将偏好保存在当前浏览器。
4. 登录后，如果账号已有语言偏好，则账号偏好覆盖浏览器默认值。
5. 账号尚无偏好时，将登录时的当前语言保存到账号。
6. 登录后的语言切换立即保存到账号，并在其他设备下次登录时恢复。

### 5.3 切换行为

- 登录页和登录后的顶部栏均显示“中文 / English”切换控件。
- 切换不改变当前 URL，不刷新页面，不丢失表单或游戏状态。
- `<html lang>`、ARIA 标签、日期和数字显示随语言更新。
- 用户录入的姓名、班级、房间名和团队名保持原文。

### 5.4 翻译范围

随界面语言切换：

- 导航、页面标题、按钮、表单字段标签和占位说明。
- 标签页、表格列名、分页、状态标签和空状态。
- 纯前端帮助文字、规则说明和无障碍标签。

固定使用中文：

- 后端 API 错误。
- 表单提交后的成功、失败和校验通知。
- CSV/XLSX 导入模板及导入错误报告。
- 成绩导出文件的列名和时间格式。

上述固定中文内容属于明确范围，不视为翻译缺失。

## 6. 账号与会话

### 6.1 登录

- 教师使用部署时初始化的登录名和密码。
- 学生使用学号和密码。
- 登录失败统一显示中文通用错误，不透露账号是否存在。
- 未登录访问受保护页面时跳转到 `/login`。
- 登录后访问错误角色页面时返回无权限状态，并导航到本角色首页。

### 6.2 学生初始密码

- 新导入学生使用服务端配置的统一初始密码。
- 第一轮不强制学生首次修改密码。
- 导入更新已有学生时不得自动重置密码。
- 教师可以单独重置或多选批量重置为统一初始密码。
- 批量重置前必须显示人数和二次确认。
- 密码重置后该学生的现有会话全部失效。

### 6.3 会话

- 会话有效期为 8 小时。
- 主动退出立即使当前会话失效。
- 会话不可存储在 Local Storage。
- 页面语言偏好可以存储在 Local Storage，但不包含认证信息。

## 7. 用户管理

### 7.1 学生列表

列表字段：

- 学号。
- 姓名。
- 班级。
- 团队。
- 创建时间。

支持按学号、姓名和班级搜索或筛选。第一轮不提供删除、停用或逐字段编辑。

### 7.2 学生导入模板

CSV 和 XLSX 使用固定中文列名：

| 列名 | 必填 | 规则                                          |
| ---- | ---- | --------------------------------------------- |
| 学号 | 是   | 1–32 字符；按文本读取并保留前导零；文件内唯一 |
| 姓名 | 是   | 去除首尾空格后 1–64 字符                      |
| 班级 | 是   | 去除首尾空格后 1–64 字符                      |

导入规则：

1. 浏览器解析文件后发送标准化行给服务端。
2. 服务端重新验证全部行并返回预览与中文错误。
3. 任意行存在错误时，不允许确认提交。
4. 学号不存在则新增；学号已存在则只更新姓名和班级。
5. 文件未出现的已有学生保持不变。
6. 提交时再次完整校验，整批成功或整批失败。
7. 单次最多 2000 行、文件最大 5 MiB。

## 8. 团队管理与学生团队

### 8.1 团队约束

- 每个团队最多三名学生。
- 每名学生最多属于一个团队。
- 团队名称全校唯一。
- 团队代码由系统自动生成并永久保持不变。
- 学生不能创建、重命名或删除团队。
- 学生可以按团队名称或代码搜索团队。
- 团队未满且学生当前无团队时，可直接加入，无需审批。
- 学生可主动退出团队。

### 8.2 比赛冻结

当团队已占用任一 `full`、`countdown` 或 `live` 房间席位时：

- 学生不能加入或退出该团队。
- 教师不能移除单个成员或清空整队。
- 团队导入不能改写该团队成员。

`open` 房间中已经占位的完整团队同样冻结；退出房间释放席位后解除冻结。

### 8.3 团队导入模板

CSV 和 XLSX 使用固定中文列名：

| 列名      | 必填 | 规则                                 |
| --------- | ---- | ------------------------------------ |
| 团队名称  | 是   | 去除首尾空格后 1–64 字符；文件内唯一 |
| 成员1学号 | 是   | 必须对应已有学生                     |
| 成员2学号 | 是   | 必须对应已有学生且不同于其他成员     |
| 成员3学号 | 是   | 必须对应已有学生且不同于其他成员     |

导入规则：

- 团队不存在则创建并生成团队代码。
- 团队已存在则更新三个成员，保留团队代码。
- 学生已经属于文件外的其他团队时整批校验失败，不自动转队。
- 文件未出现的已有团队保持不变。
- 任意团队或成员冲突时整批不写入。
- 单次最多 1000 个团队、文件最大 5 MiB。

### 8.4 教师成员重置

- 教师可移除指定成员。
- 教师可清空一个团队的全部成员。
- 操作前显示影响成员并二次确认。
- 比赛冻结期间拒绝操作。

## 9. 房间管理

### 9.1 创建房间

必填字段：

| 字段     | 规则                       |
| -------- | -------------------------- |
| 房间名称 | 去除首尾空格后 1–64 字符   |
| 比赛模式 | 只能为 1v1 或 3v3          |
| 每局时长 | 1–10 分钟整数，默认 5 分钟 |

创建成功后：

- 系统生成唯一房间代码。
- 房间立即进入 `open` 状态并出现在学生公开房间列表。
- 第一轮不支持预约时间、私密房间、房间密码或教师指定参赛者。

### 9.2 房间列表

教师列表显示：房间代码、名称、模式、时长、席位、状态、创建时间和操作。

学生列表显示：房间代码、名称、模式、时长、席位和状态，不显示教师管理操作。

支持按名称或代码搜索，并按模式和状态筛选。

### 9.3 房间状态机

```text
create
  │
  ▼
open ──席位满──▶ full ──教师开始──▶ countdown ──3秒──▶ live ──结算──▶ ended
  ▲                 │                                            │
  └──参赛方退出──────┘                                            └──只读归档

open/full ──教师取消──▶ cancelled
```

状态规则：

- `open`：未满，可加入和退出。
- `full`：席位已满，可退出；教师可以开始。
- `countdown`：不能加入或退出；三秒后进入比赛。
- `live`：不能改变席位、模式或时长；允许原参赛者重连。
- `ended`：成绩已结算，只读。
- `cancelled`：未开赛即被教师取消，只读。
- `countdown` 或 `live` 不允许取消。

### 9.4 公开抢位

1v1：

- 每个房间两名学生，分别占用 A、B 两方。
- 同一学生不能占用两个席位。

3v3：

- 每个房间两个完整团队，分别占用 A、B 两方。
- 团队任一成员点击加入，整个团队占用一个席位。
- 团队必须恰好有三名成员。
- 任一成员点击退出房间并确认后，释放整队席位。

通用约束：

- 学生同一时间只能位于一个 `open`、`full`、`countdown` 或 `live` 房间。
- 最后一个席位由服务端原子分配；并发失败者收到中文冲突提示。
- 第一名参赛者加入后，房间名称仍可修改，但模式和时长锁定。

### 9.5 开始与取消

- 教师只能在 `full` 状态点击开始。
- 不要求所有参赛者在线。
- 开始后由服务端设置统一 `startsAt` 和 `endsAt`。
- 三秒开赛倒计时不计入配置时长。
- 教师只能取消 `open` 或 `full` 房间。
- 取消和开赛操作均需要二次确认。

## 10. 2048 游戏规则

### 10.1 基础规则

- 棋盘固定为 4×4。
- 开局生成两个方块。
- 有效移动后生成一个新方块。
- 相同数字沿移动方向合并，每个方块每步最多合并一次。
- 合并后将新方块数字加入得分。
- 无位置且四个方向均不能合并时为游戏结束。
- 无效移动不生成新方块，也不增加有效移动数。

### 10.2 比赛公平性

- 同一房间所有参赛者使用同一引擎版本和随机种子。
- 浏览器只提交方向和递增操作序号。
- 服务端计算并保存权威棋盘、得分、最高方块和随机状态。
- 客户端可以显示即时预测动画，但必须接受服务端状态校正。
- 最高方块达成时间使用服务端接受有效移动的时间。

### 10.3 比赛时长

- 配置时长为 1–10 分钟整数，默认 5 分钟。
- `endsAt = startsAt + durationMinutes × 60,000`。
- 服务端以绝对时间判断剩余时间，不累计浏览器本地计时器。
- 到达 `endsAt` 后的新操作全部拒绝。
- 1v1 两人或 3v3 六人全部游戏结束时，可早于 `endsAt` 结算。

### 10.4 胜负

1v1：

1. 比较双方个人得分。
2. 同分时比较最高方块。
3. 仍相同时比较达到该最高方块的最早服务端时间。
4. 仍相同则平局。

3v3：

1. 比较双方三名成员总分。
2. 同分时比较双方成员中的最高方块。
3. 仍相同时比较该方最早达到此最高方块的服务端时间。
4. 仍相同则平局。

### 10.5 掉线和多标签页

- 掉线不暂停房间计时。
- 原参赛者在比赛结束前重新连接时恢复权威棋盘。
- 同一学生在同一房间只能有一个可操作连接。
- 新连接成功后，旧连接失去操作权。
- 从未上线或未重连的参赛者以已有得分参与结算。

## 11. 个人练习

- 仅提供不限时经典 2048。
- 不提供练习房、限时练习或排行榜。
- 正常达到游戏结束时保存一条练习记录。
- 刷新、关闭、退出或主动重新开始不保存。
- 练习记录只对学生本人可见。
- 教师成绩管理不显示练习记录。

## 12. 比赛实况与学生比赛界面

### 12.1 学生比赛界面

只显示：

- 自己的 4×4 棋盘。
- 自己的得分。
- 自己的最高方块。
- 剩余时间。
- 连接与状态恢复提示。

不得显示：

- 对手分数。
- 队友分数或团队总分。
- 他人棋盘。
- 观战人数或赛场动态。

### 12.2 教师实况界面

显示：

- 房间名称、代码、模式、状态和剩余时间。
- 1v1 两名或 3v3 六名学生的缩略棋盘。
- 每名学生的姓名、班级、得分、最高方块、在线状态和是否游戏结束。
- 1v1 双方分数或 3v3 双方团队总分。
- 当前领先方或平局状态。

点击任一学生后，以大画面显示该学生棋盘和个人摘要。该功能是棋盘状态同步，不采集或传输学生设备屏幕视频。

## 13. 成绩与导出

### 13.1 学生个人成绩

显示本人：

- 不限时练习记录。
- 1v1 比赛记录。
- 3v3 比赛记录。

字段包括日期、类型、房间、得分、最高方块、配置时长、实际时长和比赛结果。练习记录不显示胜负。

### 13.2 教师成绩管理

只显示已结束的 1v1 和 3v3 正式比赛。

支持按以下条件筛选：

- 日期范围。
- 学号或姓名。
- 班级。
- 团队。
- 房间名称或代码。
- 模式。
- 胜负结果。

教师只能查看和导出，不得修改、作废或删除。

### 13.3 导出格式

- 支持 CSV 和 XLSX。
- 导出当前筛选结果。
- 每名参赛者占一行。
- 固定使用中文列名。
- 时间转换为 Asia/Shanghai。

列包括：房间代码、房间名称、比赛模式、配置时长、实际时长、开始时间、结束时间、学号、姓名、班级、团队、阵营、个人得分、团队总分、最高方块、胜负、结束原因。

## 14. 触控与响应式要求

### 14.1 输入方式

- 手机和 iPad：只使用四向滑动，不显示屏幕方向键。
- 桌面：支持方向键和 WASD，同时允许触摸屏滑动。
- 棋盘忽略多指手势。
- 一次指针按下到抬起最多产生一步。
- 以位移主方向决定上下左右，短距离和方向不明确的手势不触发移动。
- 只在棋盘区域阻止浏览器滚动和缩放手势，页面其他区域保持正常滚动。

### 14.2 布局要求

- 棋盘始终保持正方形并完整可见。
- 手机竖屏优先显示计时、个人摘要和棋盘。
- 手机横屏允许棋盘与摘要并排，但不得横向滚动。
- iPad 横竖屏均不能遮挡导航、计时或棋盘。
- 支持安全区域内边距和移动浏览器动态视口。
- 英文长文案不得造成按钮、表格、导航或状态标签溢出。

### 14.3 验收视口

- 360×800。
- 390×844。
- 768×1024。
- 1024×768。
- 1440×900。

## 16. 验收标准

### 16.1 文档与范围

- `AC-DOC-01`：需求和架构文档均经确认后才开始业务代码改造。
- `AC-DOC-02`：生产构建不存在旧原型独立入口和已删除页面。
- `AC-DOC-03`：教师和学生一级导航与第 4 节完全一致。

### 16.2 语言

- `AC-I18N-01`：中文浏览器首次显示中文，非中文浏览器首次显示英文。
- `AC-I18N-02`：登录前后可在同一路由即时切换语言，不丢失当前状态。
- `AC-I18N-03`：登录账号语言偏好可跨设备恢复。
- `AC-I18N-04`：中英文资源键不一致时 CI 失败。
- `AC-I18N-05`：固定中文的错误、导入和导出内容不计为缺失翻译。

### 16.3 房间和比赛

- `AC-ROOM-01`：教师只能创建 1v1 或 3v3 房间。
- `AC-ROOM-02`：时长 1、5、10 创建成功；0、11、负数、小数、字符串和空值被拒绝。
- `AC-ROOM-03`：1v1 第三名学生和 3v3 第三个团队无法占位。
- `AC-ROOM-04`：最后一个席位并发抢占时只有一个请求成功。
- `AC-ROOM-05`：首个席位加入后模式与时长不可修改。
- `AC-ROOM-06`：满员后教师可在参赛者离线时开始。
- `AC-MATCH-01`：三秒倒计时结束后才开始计算配置时长。
- `AC-MATCH-02`：服务端在精确截止时拒绝新操作并只结算一次。
- `AC-MATCH-03`：全员游戏结束时提前结算并记录原因。
- `AC-MATCH-04`：掉线重连恢复权威棋盘，剩余时间不重置。
- `AC-MATCH-05`：学生无法通过 API 或 WebSocket 获取他人棋盘和得分。
- `AC-MATCH-06`：教师可查看所有棋盘并放大单人棋盘。

### 16.4 用户、团队和成绩

- `AC-USER-01`：学生导入按学号原子增量更新，并保留前导零。
- `AC-USER-02`：任意导入错误导致整批不写入。
- `AC-USER-03`：单个和批量重置密码均使相关旧会话失效。
- `AC-TEAM-01`：学生最多属于一个团队，团队最多三人。
- `AC-TEAM-02`：完整团队任一成员可代表整队加入 3v3。
- `AC-TEAM-03`：占用房间席位后团队成员关系被冻结。
- `AC-RESULT-01`：教师只看到正式比赛，学生看到本人练习和比赛。
- `AC-RESULT-02`：导出只包含当前筛选结果、中文列名和上海时区时间。

### 16.5 触控和容量

- `AC-TOUCH-01`：五个验收视口均能完整显示棋盘和主要操作。
- `AC-TOUCH-02`：手机和 iPad 无方向按钮，四向滑动各触发一步。
- `AC-TOUCH-03`：棋盘内滑动不滚动页面，棋盘外可以正常滚动。
- `AC-LOAD-01`：1000 个学生账号数据下列表和查询正常。
- `AC-LOAD-02`：60 名学生同时比赛时房间状态和结算保持正确。

## 17. 本轮非目标

- 比赛预约、赛程和淘汰赛管理。
- 私密房间、房间密码和教师指定参赛者。
- 公共观战、排行榜、消息和通知。
- 学生创建或管理团队。
- 教师账号管理、多教师权限或多学校租户。
- 成绩人工修改、删除、作废和复核。
- 繁体中文或第三种语言。
- 自定义域名和校内服务器部署。
- 设备屏幕录制、视频流或语音功能。
